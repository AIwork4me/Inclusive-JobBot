# IJ-SLM-1.0 NPU migration requirements

DX-M2 is the migration target. The Radeon gfx1151 evidence qualifies only its recorded Windows Vulkan route. DEEPX describes a DX-M2 stack with DX-LLM, model-specific optimized artifacts and an OpenAI-compatible API. The vendor API statement establishes a candidate integration surface. Admission requires direct proof for the chosen model, tokenizer, template, API features and target hardware. [DEEPX DX-M2 product documentation](https://deepx.ai/products/dx-m2/) · [Radeon workstation baseline](M0_ENVIRONMENT_REPORT.md)

| Gate | Required deployment evidence | Current result |
|---|---|---|
| Hardware and software identity | Bind device family, board and memory SKU, driver, firmware, host OS, DX-LLM/runtime build, binary SHA256 and the actual execution device. Record explicit placement and any host-executed operators. Reject silent CPU, GPU or alternate-model fallback. | NOT_RUN |
| Model conversion and provenance | Bind the original model revision, tokenizer, chat template, converter and calibration dataset hashes to the converted package. Record precision and execution placement for weights, activations and KV cache. Choose a vendor-supported export path for the exact model, then prove its reproducibility and license. | NOT_RUN |
| Local transport contract | Verify streaming and nonstreaming tools, typed arguments, raw proposal identity, stop and error semantics, cancellation, output schema and request/session separation against the same independent controls. Enable only the qualified adapter profile and preserve original output evidence. | NOT_RUN |
| Authority and offline operation | Keep tool policy, permission, writes, approval, audit and scope enforcement in the host layer. Verify the full process tree and offline operation with no external inference or service dependency. Record behavior under interrupted execution and service restart. | BLOCKED |
| Outcome equivalence | Match Radeon and NPU cases and seeds with separately registered runtimes and model artifacts. Report business facts, output contract, action sequence, redundant execution, result delivery, termination and D25 separately. Establish a task-specific quality floor before dispatch. | NOT_RUN |
| Resource envelope | Measure cold start, first token, decode and task latency, throughput, sustained memory and KV pressure, power and energy with the same independent cases at declared context and concurrency levels. Record saturation, throttling, cancellation under load and recovery. | NOT_RUN |

The existing GGUF and Vulkan setup supplies a comparison baseline. DX-M2 needs a separately identified deployable artifact and live device evidence. The public DX-AllSuite compiler documentation describes ONNX-to-DXNN for its documented path. The actual DX-M2 LLM pipeline, supported operators, formats and build versions need confirmation from the vendor package used on the target board. [Compiler documentation](https://developer.deepx.ai/tech-docs/next/DX-AllSuite/) · [JobBot inference architecture decision](../docs/decisions/ADR-001-LLAMA-CPP-PRIMARY-INFERENCE.md)

## Matched measurements

Freeze the task roster, decoding, tokenizer and runtime policy before comparing resource arms. Count physical attempts, evaluable outcomes and blocked telemetry independently. Use distinct profiles for each quantization package, context setting and concurrency level. Each arm records latency distributions, input/output tokens, peak host and accelerator memory, accelerator utilization, and host/device power where instrumented. Report attempts and summed measured cost per correct business fact, strict output, verified execution and scoped qualified completion. This experiment uses the separate hardware and NPU allocation.
