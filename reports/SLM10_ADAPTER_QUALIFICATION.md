# IJ-SLM-1.0 SDK adapter qualification

Six opt-in profiles provide independently selectable treatments. The reference returns the identical request bytes and leaves callback and final decisions to the existing SDK and host. Each treatment declares a version, input, output and reference. The live diagnostic runner and the frozen benchmark retain their existing entry points. [Profile registry](../atlas/slm/v1.0/sdk-adapter-profiles.json) · [Implementation](../benchmarks/slm10/sdk_adapters.py)

| Component | Comparison and software result | Overhead and scope |
|---|---|---|
| Prompt Compiler | PASS on nine portable SDK requests against a byte-identical reference. Only the digest-bound SDK system message could lose the single Markdown directive. Missing or ambiguous directives and unbound system inputs were passed through. | Removed 51 request bytes per captured case. Bounded JSON decoding, system digest comparison and serialization. Test the exact SDK build and preserve every authorization and workflow directive. |
| Compact Result Codec | PASS on nine SDK requests after a successful callback. The independent checker compared the original wrapper result, compact result and remaining request fields. It rejects mismatched arguments, result values, malformed wrappers and duplicate JSON keys. | Removed 159–170 request bytes. Parsing cost depends on the number and size of verified deliveries. Applies to the observed SDK wrapper and precise bounded JSON objects. Errors and deliveries without trusted correlation retain their original packaging. |
| Action State | PASS on nine post-callback requests. Completed action IDs and tool names came from successful executions tied to both a provider proposal and a visible delivered result. Cross-scope callbacks, host cache replays and missing actions were excluded. | Added 207–208 request bytes. Processing includes receipt verification and summary serialization. Repeated legal actions still belong to the existing workflow. |
| Duplicate Execution Guard | PASS on synthetic software controls for explicit permission, unchanged resource and scope, immutable freshness, a new provider call, audit availability and cancellation. Controls covered writes, recovery, deliberate repeats, scope changes, principal, role and session separation, failure and expiration. | Per-run bounded memoization, strict argument parsing, cancellation checks and mandatory audit. The selected reuse receipt holds a result digest and source identifiers. The caller tracks successful delivery separately. Host protection leaves model proposal counts and model-effect credit untouched. |
| Termination Policy | PASS on synthetic exact-stop and continuation controls. Controls rejected cancellation, timeout, incomplete transport, pending calls and authority, incomplete workflow and exhausted budgets. | Constant-sized comparison of authoritative provider, SDK and workflow state. It can veto an invalid final boundary. A model must still emit a valid stop and any required output. |
| Structured Output Contract | PASS on synthetic terminal and exact JSON controls. Fences, duplicate keys, malformed JSON, unexpected fields, disallowed values and pre-terminal inputs were rejected. | Bounded strict parsing and schema validation. Validation cost depends on the supplied schema and result. Schema success concerns the supplied contract. Existing workflow, scoring and authority checks continue to govern factual and business requirements. |

The archive replay ran 27 comparisons over nine portable requests in the three sealed pilots. Its evidence links each candidate to the sealed report digest, model and runtime identifiers and both published and original request digests. The published reports redact local identities, so the original request digest and the portable replay digest have separate fields. The recorded passes qualify software transformations over published bytes. Fresh physical adapter effects, holdout execution and formal attribution remain pending, with zero formal trials attributed to these comparisons. [Replay evidence](../evidence/IJSLM/sdk-adapters/archived-request-controls.json) · [Replay command](../benchmarks/slm10/sdk_adapter_qualification.py) · [Historical physical arms](SLM10_SDK_SPECIALIZATION_AB_TEST.md)

From the repository root with the project Python environment, run `python -m benchmarks.slm10.sdk_adapter_qualification` to reproduce the digest-bound file. Add `--timings` to collect request transformation times in the current process. These elapsed times include the request measurement and hashing. Provider token counts, inference time, callback blocking, audit sink I/O and wall time require their own measurements in a running matched SDK experiment.
